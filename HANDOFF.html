一分钟速览

这个仓库有两条实现线，别搞混：

  • main（f9731c9，1.2.28）：旧的 Jetpack Compose 版，只做对照，不动。
  • lvgl / lvgl-working：C + LVGL 9.2.2 版，全部业务在 NDK 里，Android 侧只有一个 SurfaceView 宿主。日常开发在 lvgl-working，合入 lvgl。

本次会话在这个 LVGL 线上做了四类事：

  1. 分支整理：重建又删掉 lvgl-main-parity，新建 lvgl-working（以 lvgl 为基线），之后一直保持同步。
  2. 三项功能/性能调整：屏幕容器改成 LRU 只留最近 2 屏、LaTeX 命令不再报红改灰色提示、新手引导第 3/4 步必须真的点一下高亮区。
  3. 工程化：新增 tools/setup-sandbox-toolchain.sh（一条命令装 SDK/NDK/Gradle），修了它一个 gradle-8.7 vs gradle-8.7-bin 的 bug。
  4. 发版：beta-0.4 与 beta-0.5 两个 GitHub Release，各 5 个签名 APK。
最重要的一条：这个沙箱会周期性重置。.toolchain/、/tmp/、git 的 origin/lvgl 远程引用、remote.origin.fetch 配置都会被清掉，工作区甚至会被自动 commit 成 feat: update workspace 后重推。每次开工先做「环境体检」（见 playbook 第 0 步）。

沙箱重置时会丢的东西

  • .toolchain/（SDK、NDK、Gradle 缓存）
  • /tmp/（我之前放在那的截图、脚本草稿全丢过）
  • git 的 refs/remotes/origin/* 和 remote.origin.fetch（默认只剩 main 一条 refspec）
  • 可能丢掉本地未提交改动；沙箱还会把工作区自动 commit 成 feat: update workspace 并推送
  • ~/.android/debug.keystore（签名指纹会变 → 新包无法覆盖旧包）
因此：任何需要留存的产物都放 /workspace 下的 git 跟踪路径，或立刻上传到 GitHub Release；/tmp 只放一次性中间文件。

④ 修脚本的 Gradle 404

用户实际运行时脚本 exit=22：变量写成 GRADLE_DIST_VER=gradle-8.7，而真实文件是 gradle-8.7-bin.zip，wrapper 缓存目录也是 gradle-8.7-bin/，于是三个源全部 404。

修复内容：

  • 变量改为 GRADLE_DIST=gradle-8.7-bin，全脚本统一引用
  • 新增 fetch()：逐源重试，判据为「文件非空」，Gradle 还要 unzip -t 校验
  • Gradle 三个源：services.gradle.org → downloads.gradle.org → 腾讯云镜像（官方源现在 307 跳 GitHub Release，容易 404）
  • SDK 组件同样支持镜像失败退回 dl.google.com
  • 全部失败时打印手工补救路径，不再静默退出

验证：rm -rf .toolchain 后从零跑，exit=0，工具链就绪。

第 0 步：环境体检（每次开工都跑）

cd /workspace

# 1) 补 fetch refspec（重置后只剩 main，看不到 origin/lvgl）
git config --local remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"
git fetch origin

# 2) 确认三条线的位置
git branch -vv
git ls-remote --heads origin | grep -E "lvgl|main"
git log --oneline -3

# 3) 看 release / PR
gh release list --limit 3
gh pr list --state open

# 4) 工具链在不在
ls .toolchain/android-sdk/ndk 2>/dev/null || echo "需要重装"

第 1 步：装工具链（约 1~2 分钟，2.5 GB）

bash tools/setup-sandbox-toolchain.sh

# 或装完直接构建：

脚本失败时会打印手工补救路径；Gradle 三个源都挂了就把 gradle-8.7-bin.zip 放进 ~/.toolchain/gradle-home/wrapper/dists/gradle-8.7-bin/bhs2wmbdwecv87pi65oeuq5iu/ 再 touch 同名 .ok。

第 2 步：改代码 + 冒烟（不需要 Gradle / 模拟器）

冒烟脚本会覆盖已提交的截图；确认差异是否符合预期再提交。别把输出指到 /tmp，会丢。

第 3 步：构建 release

export ANDROID_HOME=/workspace/.toolchain/android-sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME
export GRADLE_USER_HOME=/workspace/.toolchain/gradle-home
export JAVA_HOME=/root/.local/share/mise/installs/java/17.0.20+101   # 默认 java 是 25，Gradle 8.7 不支持

sh ./gradlew :app:assembleRelease -PabiSplits :app:assembleDebug
-PabiSplits 对 debug 也生效：不会产出 app-debug.apk， 而是 app-<abi>-debug.apk 和 app-universal-debug.apk。 发版时用 universal 那个。

第 4 步：签名（5 个包，v1+v2+v3）

APKS=/workspace/.toolchain/android-sdk/build-tools/34.0.0/apksigner
KS=~/.android/debug.keystore
OUT=/workspace/dist/beta-0.6 && mkdir -p $OUT

$APKS sign --ks "$KS" --ks-pass pass:android --key-pass pass:android \
  --ks-key-alias androiddebugkey \
  --v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled true \
  --out $OUT/FunctionDrawer-beta-0.6-release-universal.apk \
  app/build/outputs/apk/release/app-universal-release-unsigned.apk

# 校验必须显式给 --min-sdk-version 21，否则 v1 会被误报成 false
$APKS verify --min-sdk-version 21 $OUT/FunctionDrawer-beta-0.6-release-universal.apk

# 看证书指纹（每次重置都会变，写进 release notes）
$APKS verify --min-sdk-version 21 --print-certs $OUT/FunctionDrawer-beta-0.6-release-universal.apk | grep "SHA-256"
